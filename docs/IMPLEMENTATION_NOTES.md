# 第一階段實作紀錄（原型）

> 本文件記錄第一階段「可在手機直式瀏覽器操作的遊戲原型」的技術選擇、規則落點、假設與未完成項目。
> 規格來源：`docs/spec_v0.2.md`、`docs/data_v0.2.json`；C＝使用者確認，P＝既有提案，N＝原型起始值。
> 這是可玩的原型，不是已平衡、已上線或已實機驗收的遊戲。

## 1. 技術選擇（決策矩陣）

| 決策點 | 方案 | 複雜度 | 技術債 | 風險 | 採用 |
| --- | --- | --- | --- | --- | --- |
| 權威結算位置 | A. 本機 `GameEngine`（純 TS，扮演伺服器＋戰鬥 worker），UI 只送命令 | 低 | 低：命令契約、操作去重、帳本與伺服器版同形，可直接搬到 Node 服務 | 本機存檔可被玩家竄改（原型可接受） | ✅ |
| | B. 現在就建 Fastify＋PostgreSQL | 高 | 低 | 需資料庫與部署，第一階段無法專注驗證玩法 | 下一階段 |
| 戰場繪製 | A. DOM／CSS 幾何佔位（`BattleViewport`） | 低 | 中：特效多時需換 Canvas | 大量特效效能不足 | ✅（第一階段） |
| | B. PixiJS 8（規格 N 建議） | 中 | 低 | 需處理非同步初始化、Canvas 可及性；美術未交付時收益小 | 美術交付後評估 |
| 套件結構 | npm workspaces：`packages/content`、`packages/game-core`、`apps/mobile-web` | 中 | 低 | — | ✅ |

採用理由：規格要求「若不影響核心可執行原型，採最小且可替換的實作」。遊戲核心不依賴 DOM／React（`packages/game-core/tsconfig.json` 只含 `ES2023` lib，誤用 DOM 會直接型別錯誤），日後可原封不動放到伺服器。

### 鎖定版本（2026-11-05 查詢 npm registry）

TypeScript 7.0.2、Vite 8.3.5（以 root `overrides` 統一）、React／React DOM 19.3.1、@vitejs/plugin-react 6.1.2、Vitest 5.1.0、Zod 4.6.7、@playwright/test 1.63.0（對應環境預裝 Chromium）。
Vitest 5.0.5／4.1.x 在 npm 10.9.9 會觸發 arborist `edgesOut` 錯誤，因此改用可正常安裝的 5.1.0。

## 2. 目錄與分層

```
packages/content    內容資料：讀取 docs/data_v0.2.json（單一來源）＋ Zod 結構驗證＋穩定 ID 轉換
                    tuning.ts（全部 N 數值）、effects/（技能／被動／傳說特效的效果策略資料）
                    encounters.ts（5 種小首領模板、12 張圖 BOSS 機制）、validate.ts（內容自動檢查）
packages/game-core  純邏輯：rules/（公式、屬性、抽裝、穿戴合法性）、services/（每個命令一個交易函式）
                    battle/BattleSim.ts（固定 50ms 邏輯刻）、engine/GameEngine.ts（命令去重、時間推進）
apps/mobile-web     host/LocalGameHost.ts（計時器、背景暫停、存檔、分頁 lease、自動鑑定逐筆送出）
                    ui/（冒險、角色、技能、圖鑑四頁＋共用底部面板）、styles/tokens.css（設計 Tokens）
```

- UI 只能透過 `host.send(command)` 改變狀態；按鈕停用原因直接呼叫核心的 `assert*` 驗證器（`availabilityOf`），不在 UI 重寫一套規則。
- 技能以效果策略組合（damage／applyStatus／spawnUnit／selfBuff＋觸發器 proc），新增技能只需加資料；沒有 35 個職業各一份戰鬥引擎。

## 4. 實作假設與暫定值（全部可調，非使用者核准）

1. **首次自動挑戰（P）預設關閉**：使用者第一階段要求「手動召喚 BOSS」為主循環；可在「更多」開啟，每張圖最多自動一次。
2. **revision 只計玩家命令**：戰鬥產出（古物點）不增加 revision，否則自動鑑定會不斷撞到 409。多分頁衝突改由分頁 lease 防護。鑑定台升級另帶 `expectedBenchLevel`。
3. **命令先結算時間**：`execute()` 會先把戰鬥推進到命令時間，BOSS 已在截止前擊敗時，之後送達的「退出」不能改寫結果。
4. **可重試的拒絕不封存**（古物不足、滿包、金幣不足、BOSS 中），同一操作 ID 稍後可重試；格式錯誤等不可重試的拒絕會封存。
5. **BOSS 中凍結**：鑑定、出售、升台、換裝、轉職、技能配置都停用；鎖定／解鎖允許（不影響戰力或資源）。
6. **自動鑑定**：古物不足時等待並在有古物後自動繼續；遇到符合保留條件的裝備暫停，玩家處理面板後繼續（若當時已有其他面板開著，關閉後才自動開啟該件）；自動出售永遠不處理史詩以上（`tuning.identify.autoSellMaxAllowedQuality`），首次開啟或擴大出售範圍（提高品質上限、增加部位、放寬保留條件）都要再次確認；保留條件依規格順序提供品質、部位、詞條。
7. **兩套配置**：穿戴只改目前檢視的配置（清怪／打王）；召喚 BOSS 面板會提示兩套不同並提供「複製清怪配置到打王配置」（玩家主動操作）。
8. **轉職**：未實作技能的路線不可解鎖（顯示「原型尚未實作」）；第一次解鎖職業後，產出路線自動由「見習者」改為該職業（見習者不是可選路線）。
9. **戰鬥細節 N**：命中最少延後 1 個邏輯刻（50ms）；迅影刺兩段間隔 150ms；萬劍歸流 6 段間隔 200ms；易傷以加總計算；副目標護甲沿用本體基礎護甲；BOSS 易傷窗口放在每循環最後一段；目標死亡時已發出的單體命中落空（不轉向）。
10. **冷卻記憶**：技能移出配置再放回、換職再換回都沿用原冷卻，避免重置冷卻刷產出。
11. **存檔**：本機 `localStorage`；只保留最近 400 筆操作、600 筆帳本、300 件已售封存（`tuning.persistence`）。
12. **普通戰鬥重新整理**：重開當前關卡第 1 波，不補算離線收益；BOSS 依原截止時間以同一快照與種子重播結算。
13. **短螢幕版面**：高度 < 720 或字體放大時，上方內容在內層捲動、鑑定主操作列固定在底部（不被導覽蓋住、也不蓋住其他按鈕）；640～719 的「篩選／路線」列移到鑑定台列下方（規格允許必要時移位，不縮觸控區）。
14. **返回鍵**：每開一層（面板、確認對話）推一筆歷史；返回先關最上層，只有確認對話時也不會離開遊戲。
15. **BOSS 挑戰中的召喚按鈕**：不再佔用戰場右下角（會蓋住 BOSS 名稱），改在 BOSS 血條列顯示「挑戰中・不可重複召喚」。
16. **開發夾具**：開發模式的「更多」頁可直接載入 Lv80 劍聖／機械統帥等前置狀態，用來在手機上檢查二、三轉機制；正式建置不包含。

> 差異機制提醒：一轉七職業都是「單體＋範圍」兩招加一個追加被動；明顯不同的機制（戰意、多段、固定總量絕招、砲台／機甲召喚）從 Lv40 二轉開始。正常遊玩第一張圖約到 Lv10～15，要實際看到二、三轉機制請用開發夾具或單元測試。

## 6. 第二輪：內容補完、數值平衡、美術與介面

### 6.1 內容補完
- 35 個職業節點全部可玩：70 招、35 個被動、88 件傳說特效全部有實作效果（`packages/content/src/effects/`），內容測試確認沒有任何「尚未實作」的條目。
- 新增戰鬥原語：角色資源（專注、連擊點、氣脈、熱度）、可疊層狀態（破陣、寒霜、聖印）、獨立毒層與毒爆、指定來源易傷（弱點、破綻）、常駐戰獸與協同段、幻影／替身共用上限與提前結算、星陣（區域持續，傷害來源為持續傷害）、花色輪轉與切牌、次數型增益（符文刻印）、死亡轉移（印記、聖印、破甲、破綻）、多種傳說觸發（最後一段、首殺、狀態自然到期、增益結束、主目標死亡、同目標持續等）。
- 一層追加鏈：追加、持續、召喚傷害不觸發被動或傳說；例外只有規格明寫由召喚命中觸發的兩條（默契追獵、狼牙骨笛），其效果本身也不再觸發。
- 驗證：`all-jobs.test.ts` 讓 35 個職業掛上路線全部傳說跑刷怪 90 秒與打王 60 秒，檢查不崩潰、無追加遞迴、資源與層數不超上限、召喚上限、配置中每招都有出手、BOSS 同種子重播一致；`route-mechanics.test.ts` 逐條驗收新機制。

### 6.2 第二輪實作假設（N，可調）
1. **切牌**只改下一張的花色，花色指標照常前進一格（不造成額外出牌）。預定花色為黑桃。
2. **連環牌擊**「單目標可集中」解讀為：多名敵人時 3 張牌依序輪替目標，只有一名時集中主目標。
3. **「結束後」類傳說**在該技能最後一段結算時觸發；「最後一段命中後」要求最後一段實際命中。**「只有一名目標時」**在施放時判定（第一個傷害步驟只選到 1 名；沒有傷害步驟的技能看場上敵人數）。
4. **餘箭追獵**適用於星隼遊俠路線的所有本體單體命中（普攻與技能），原目標死亡時重選一次。
5. **獸王號令**先套用戰獸 +40% 增益，再打出立即協同攻擊。百獸獵弓的「戰獸追擊」以追加傷害實作（不暴擊、不再觸發）。
6. **專注**：命中同一主目標才累積；主目標被擊殺保留 1 層（擊殺那一下先計入再套保留）；仍存活的舊目標被換掉時歸零。
7. **等待條件只等做得到的事**：技能的優先條件若目前配置沒有任何來源（例如沒帶切牌卻等「切牌後」、沒帶弱點標記卻等「標記後」），視為成立直接施放，不再每次白等 3 秒。
8. **毒爆**依剩餘時間由短到長消耗，保留最長的一層；剩餘傷害以各層自己的攻擊快照計算後乘 80%，以持續傷害來源一次打出。
9. **替身**本身不攻擊，自然到期或被提前結算時爆炸；**幻影**被提前結算時補一擊，自然到期不補；被終幕禮炮消耗的單位直接移除、不結算。

### 6.3 數值平衡
- 平衡報告：`npm run balance`（本機離線執行，寫入 `docs/BALANCE_REPORT.md`，規格 §891 不使用 CI）；單路線傷害拆解：`npm run balance:breakdown -- JOB03`。
- 同投入定義：相同等級、裝備等級＝等級、全身稀有、只計主屬性；各路線屬性完全相同，只比較職業機制。參考等級 L(m)=10m 是假設。
- 結果：14 條三轉路線同投入清怪在 5 個檢查點（第 8～12 圖）全部落在中位數 ±15% 內。打王比較與二轉路線仍有超出 ±15% 的路線，列在報告「觀察與待決策」。
- 所有與設計倍率不同的地方集中在 `packages/content/src/effects/balanceAdjustments.ts`（附原因）；驗證器只接受清單內的差異，清單條目失效也會報錯。

### 6.4 字型
- 決策：只自架 **粉圓 Huninn**（@fontsource/huninn 5.3.1，OFL-1.1）作標題、按鈕、數字；內文使用系統字型（iOS PingFang TC、Android Noto Sans CJK）。
- 理由：Noto Sans TC 自架兩個字重會讓建置輸出多約 70MB；Huninn 依 Unicode 範圍分 111 個切片，手機只下載畫面用到的字。Huninn 只有一種字重，套用處一律 400，避免瀏覽器合成粗體。

### 6.5 美術（出圖）
- 全部為程式內嵌的原創向量圖（`apps/mobile-web/src/art/`），不載入外部圖片、不使用點陣圖；換正式美術時只替換此資料夾，呼叫端介面不變（`art/types.ts` 的契約）。
- 內容：36 個角色外觀（見習者＋35 職業節點，依職業系／轉職階段／分支變化）、7 個職業系徽章、108 隻怪物（每圖 6 普通＋5 小首領＋1 BOSS）、12 個 BOSS 副目標、12 張地圖背景（依小區切換光線）、介面圖示、8 個部位圖示、88 件裝備圖示、70 個技能圖示、6 種召喚物／區域（戰獸、幻影、替身、砲台、機甲、星陣）。
- 套用位置：戰場（背景、角色、怪物、BOSS、副目標、召喚物、區域）、資源列頭像、底部導覽、技能列、裝備格、背包卡片、裝備／技能／BOSS 面板、職業樹、圖鑑（未發現者只顯示剪影）。
- 開發模式 `?gallery=1` 可一次檢視全部美術；`art/__tests__` 以伺服器端渲染驗證每個 ID 都有對應圖、沒有重複的 SVG id。
- 這是原型美術，不宣稱為最終美術。

### 6.6 效能
- 戰場每 50ms 依快照重繪；向量圖與戰況無關，因此在戰場、技能列、裝備格以 `memo` 包裝，未變動的 SVG 不重建。
- 本機量測（開發模式、Chromium、4 倍 CPU 降速、390×844、機械統帥 Lv80 夾具、10 秒）：接上美術後未 memo 為 59 個長任務、26 fps；memo 後 9 個長任務、52 fps。
- 正式建置（vite preview、同條件、全新存檔）：0 個長任務、60 fps。正式建置沒有開發夾具，後期大量召喚物的正式建置數據與實機數據尚未量測。
- 建置分塊：程式、第三方、設計資料、美術各自一塊；粉圓的 @font-face 表（約 90KB gzip）改為首屏後非同步載入，不阻擋第一次繪製；實測首頁只下載 9 個字型切片、不下載 woff 備援檔。

### 6.7 存檔相容
- 第二輪沒有改動存檔結構（角色、裝備、配置、進度欄位不變），技能與傳說效果都由內容目錄讀取，因此內容版本維持 `0.2-proto.1`，第一階段的本機存檔可直接沿用。
- 為什麼不升版：目前讀檔遇到不同內容版本會拒絕（原型尚未提供遷移），升版會讓既有存檔無法載入。
- 已知邊界：若存檔當下正在打 BOSS，重新整理後會以新的技能數值重播該場，結果可能與舊版不同。正式服務前需要「內容版本＋遷移」機制。
