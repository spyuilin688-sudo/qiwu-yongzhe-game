### 關鍵判斷

首次自動挑戰、60秒、小首領不設時限，均為 P／N 提案。BOSS 同一刻死亡與時間到，以有效命中時間≤截止時間的擊殺先判成功。挑戰失敗時，首次自動挑戰旗標不重置；重新登入也不能再次自動召喚。

普通戰鬥切頁不停止，進角色／技能頁仍可累積已核實的古物；真正切到手機背景則按背景策略暫停。BOSS 計時不因開面板、切頁或斷線而暫停。

## 鑑定與出售：每一步的結算順序

### 遺物鑑定台的形式

折疊木桌、黃銅透鏡、刻盤與符文拓印紙。消耗一件未鑑定古物，透鏡掃描後顯示裝備。單次操作不收金幣、不需鑰匙、不需鑑定券。升級立即生效，只影響之後的鑑定。

| 順序 | 鑑定一次 | 失敗時 |
| --- | --- | --- |
| 1 | 驗證登入、操作ID、角色版本與非BOSS狀態。 | 拒絕操作，不扣任何資源。 |
| 2 | 鎖定角色錢包、背包容量與該次請求。 | 同操作ID已成功就回原結果，不能重抽。 |
| 3 | 記錄操作前角色等級、鑑定台等級與目標職業路線。 | 路線／資料版本無效，整筆回滾。 |
| 4 | 確認古物≥1、背包未滿；扣1古物。 | 不足或滿包不給經驗，也不生成裝備。 |
| 5 | 依操作前等級生成1件裝備，固定品質／詞條／特效。 | 生成錯誤時回滾扣除。 |
| 6 | 加本次經驗；連續升級則逐級扣除門檻並保留餘額。 | 角色等級只由經驗結算導出。 |
| 7 | 寫裝備、帳本、結果與新版本後提交。 | 提交前失敗皆回滾；提交後斷線則可查回。 |
| 8 | 回傳結果，畫面播放鑑定動畫與比較面板。 | 動畫重播、跳過或關閉不再結算。 |


### 自動鑑定

手動與自動共用同一條服務流程；自動只是按序發送「鑑定一次」。同一時間最多一筆進行中，建議最短顯示節奏500毫秒。收到可保留裝備、滿包、古物不足、斷線、BOSS開戰或手動暫停時停止發下一筆。不能預先一次扣100件，再假裝逐件動畫。

### 出售

售價由伺服器以裝備實例計算。已穿戴、任一配置引用、已鎖定、已出售與不屬於本人者皆拒絕；多件出售採全成全敗，錯誤指出衝突項目。穿戴新裝只替換欄位，不出售舊裝。保留與鎖定分開：保留是收進背包，鎖定是禁止出售。

### 裝備產出規則

Lv1～9尚未選職業時，只從六個共用部位等權抽取。完成一轉後，八個部位等權抽取；主武與副手只從所選已解鎖路線及其祖先基底抽取。共用部位從該部位三種基底等權抽取。品質、部位、基底、詞條依固定順序抽選，記錄內容版本。

玩家可以在鑑定設定選已解鎖的目標路線。切換目標只影響新裝備，不改目前職業、不把舊裝重抽。高階基底需符合轉職階段與等級；當某池為空，回退同部位最近祖先池，不默默跨職業。

### 金幣用途與升級交易

本版金幣只用來升級鑑定台，不增加修理、轉職或技能升級費用。升級時以目前台等重新計價並鎖定錢包；不足顯示差額，不能扣成負數。禁止在BOSS挑戰中升台。

### 先處理風險，再調數字

若某職業清怪慢20%，其古物、經驗與金幣會同時落後，這不是單純「打王較強」可以完全補回。原型測試先要求同投入的14條路線清怪產出落在中位數±15%內，再比較打王強弱。此±15%是驗收目標，不是現有測試結果。

## 戰鬥計算、冷卻與事件順序

| 項目 | 實作規格 |
| --- | --- |
| 計算攻擊 | A=(角色基礎攻擊+主武固定攻擊+副手固定攻擊)×(1+攻擊加成總和)。百分比使用萬分位整數。 |
| 本體直接傷害 | D=floor[A×技能係數×(1+對應傷害加成)×暴擊倍率×護甲係數×受傷增益]；最後至少1。 |
| 護甲係數 | ArmorFactor=400/(400+max(0,敵方護甲×(1−破甲比例)×(1−穿透比例)))。多個破甲取最大，不相乘。 |
| 暴擊 | 只對標示可暴擊的本體直接傷害抽取；初始暴擊率5%、倍率1.5。暴擊率上限75%，倍率上限3.0。 |
| 持續／召喚傷害 | 預設不暴擊；分別套持續傷害或召喚傷害加成。A已含本體攻擊加成，不再重乘同一攻擊加成。 |
| 攻速／冷卻上限 | 普攻攻速加成上限100%，即最快0.5秒1次；冷卻縮減上限40%。兩者分開，攻速不加快技能冷卻。 |
| 一次行動 | 一次普攻／技能對應唯一action_id；多段命中沿用該ID。普攻計數、戰意等按明確來源標籤計，不按動畫段數。 |
| 施放排程 | 每50ms推進一次邏輯，與30／60fps畫面獨立。常規技能與絕招共用250ms施放鎖；按玩家順位選第一個可施放技能。 |
| 避免永遠等條件 | 一般資源門檻最多等3秒後允許基礎施放；只有缺乏必要對象如「沒有砲台可超頻」時才持續跳過。 |
| 命中快照 | 普通戰鬥可換裝；已發出的投射物沿用施放時快照，新行動用新屬性。BOSS整場使用開戰快照。 |


### 同一邏輯刻的固定順序

讀取截止前的合法輸入 → 到期／持續傷害 → 已排程命中 → 清理死亡 → 一次性產出與過關 → 生成下一波 → 排程普攻／技能 → 發送畫面事件。若到期刻正好死亡，先依命中時間完成勝負判定，再處理逾時。

核心使用固定種子亂數與固定排序；相同版本、快照、種子與輸入必須能重播相同結果。畫面時間、掉幀、特效開關與動畫快轉不能改掉落或勝負。

| 分類 | 必須遵守的規則 | 測試重點 |
| --- | --- | --- |

### 目標選擇

普通戰鬥：玩家預設主目標 → 尚存最早生成敵人。範圍攻擊按主目標、生成序處理，最多3名；一般技能不因目標少就補足空段，只有技能明寫集中／固定總量才可以。

BOSS戰：預設主目標始終為本體。副目標由範圍技能或玩家在開戰前設定「優先機制目標」處理；開戰後不新增精準手操找真身需求。所有BOSS本體全程可攻擊。

### 自動鑑定篩選：先保護再處理

保護順序：配置引用／已穿戴／鎖定 → 首次取得傳說基底 → 符合玩家保留條件 → 其他。預設所有史詩以上先暫停讓玩家看；自動出售必須由玩家主動開啟並確認條件。

同一物品符合保留與出售條件時，保留優先。篩選條件只決定處理方式，不影響生成機率。規則版本隨請求保存，設定改動只從下一筆鑑定開始。

### 動畫時機

伺服器回傳成功後才播放還原動畫，建議600ms內完成；跳過只加快顯示，不加速服務結算。一般品質不蓋全螢幕；新傳說可在面板內突出顯示，不遮住BOSS計時。

### 共用選項元件

技能條件、品質、部位、職業選擇都共用選單面板。選項圖示24～28，文字14～16，點擊列至少48；選項多於8個才提供搜尋。不要每個頁面各寫一套字型與彈窗尺寸。

### SOLID 的實際落點

技能以效果策略組合：DirectDamage、ApplyStatus、ConsumeStacks、SpawnUnit、ModifyCooldown、TransferStatus，而不是35個職業各複製一份戰鬥引擎。新增技能需新增資料或一個明確策略，不修改所有職業switch。

亂數、時鐘、內容查詢與資料儲存經由介面注入。測試可以用固定時鐘與種子；正式環境換成伺服器實作，遊戲核心不用改。按鈕依賴命令服務，不直接依賴資料庫。

### 避免過度設計

初版使用模組化單體API與單一戰鬥worker程序即可；不先拆十個微服務。玩家量與效能測試證明需要後，才拆負載或加快取。所有數值集中內容表，禁止散落Magic Numbers。

## 伺服器與客戶端的權責、同步

| 資料／行為 | 權威端 | 同步方式 |
| --- | --- | --- |
| 金幣、古物、經驗、台等 | 伺服器 | 交易成功回傳新revision與增量；本機不得自行確認。 |
| 裝備品質、詞條、特效 | 伺服器 | 鑑定結果固化成物品實例，不由前端亂數生成。 |
| 敵人生命、技能CD、BOSS時限 | 戰鬥worker | 每200ms推送快照／差量，畫面插值；重要結算另發持久事件。 |
| 普通戰鬥成長變更 | API＋worker依序套用 | 交易成功形成變更命令；下一個安全tick套用，已發射技能沿用原快照。 |
| 畫面捲動、面板開關、音量 | 客戶端 | 可保存本機偏好；不帶來經濟效果。 |
| 預覽傷害 | 客戶端沙盒或查詢服務 | 固定測試模型，明確標示估算，不能變成正式獎勵憑證。 |
| 內容版本 | 伺服器發布 | 以content_version與checksum校驗，整場戰鬥固定版本。 |


### 連線與背景策略 N

普通戰鬥僅在有效線上會話運作。正常切到角色／技能頁仍是同一會話；切手機背景時發暫停命令並停止渲染。若突發斷線，伺服器在最後有效心跳後最多容忍3秒，隨後暫停；重連不補算長時間離線收益。

背景頁面的動畫與計時器可能被瀏覽器節流，因此不能以requestAnimationFrame或setTimeout當真實獎勵時間來源。[T7]

BOSS不同：建立後依伺服器時間最多跑60秒，即使背景或斷線也不暫停；重連取得既有結果，不再開一場。這是已開始挑戰的完成，不是離線刷怪收益。

### 多裝置與版本衝突

同帳號一次只允許一個可寫戰鬥會話。新裝置登入時提示接管，伺服器撤銷舊lease；舊頁只讀，不能雙開鑑定。每個經濟命令帶expectedRevision，過期則回409並刷新，不自動用舊資料覆蓋。

### 物品實例不可只存名稱

裝備基底代表名稱、部位、可用路線與傳說效果；物品實例保存這一次抽出的等級、品質、詞條值與版本。內容表日後改名，不應把已賣裝備重新生成，也不能讓相同名稱的兩件裝備共用鎖定狀態。

### 型別與帳本

資料庫資源以64位整數保存；前端超過安全整數範圍時使用BigInt／十進位字串，不以Number浮點拼接金額。百分比用basis points（萬分位整數），時間用整數毫秒，ID使用不可猜測值。

前端快取只作顯示，不可把快取餘額回灌正式資料。資料庫備份需做實際還原演練；還原後對照操作與帳本，不能讓已成功操作在重試時再次獲利。保存時間、帳號恢復與正式認證方式原文未指定，上線前必須另定。

# 09｜API 契約與錯誤處理

以下是預定實作契約，不是已存在的服務網址。所有寫入都從驗證過的登入會話取得player_id，不接受玩家傳入他人的player_id。讀取回應含contentVersion與revision。

| 項目 | 實作規格 |
| --- | --- |
| 寫入共同外層 | operationId:不可重複操作ID；expectedRevision:十進位字串；payload:該命令資料；contentVersion:已載入版本。 |
| 成功回應 | operationId、status=succeeded、revision、result、wallet、playerSummary。重試成功操作回同一份結果，不生成新的裝備。 |
| 錯誤回應 | code、message、retryable、currentRevision、fieldErrors；可恢復錯誤說明下一步，禁止只顯示「發生錯誤」。 |
| 結果查詢 | GET /v1/operations/{operationId} 可查unknown/pending/succeeded/rejected。傳輸逾時先查原ID，不能直接新建ID重做。 |


| 方法／路徑 | payload／查詢參數 | 結果與限制 |
| --- | --- | --- |
| GET /v1/state | 無 | 完整玩家、錢包、配置、活動挑戰與內容版本。 |
| GET /v1/content/{version} | 已支援版本 | 不可變內容資料與checksum。 |
| GET /v1/items | slot、quality、cursor、limit≤50 | 本人未售出物品與下一頁cursor。 |
| POST /v1/identify | targetJobId、settingsVersion | 扣1古物；產1裝備與經驗。BOSS／滿包拒絕。 |
| POST /v1/items/sell | itemIds:1～50、origin:manual/auto | 全部驗證後一次出售；gold增加，XP不變。 |
| POST /v1/items/lock | itemId、locked:boolean | 只改鎖定；被出售者拒絕。 |
| POST /v1/equipment/equip | itemId、loadoutId、slot | 驗證路線／等級；舊裝留背包。 |
| POST /v1/bench/upgrade | expectedBenchLevel | 伺服器計價、扣金幣、台等+1；不直接給經驗。 |


POST的成功狀態不取代授權；每個itemId與loadoutId都要重新驗證所有權。JSON輸入拒絕未知欄位與超長陣列，不允許額外傳sellPrice、qualityRoll或rewardAmount控制結果。

## 交易實作：只結算一次，而不是只禁用按鈕

### IdentifyService.identifyOnce

輸入：已驗證玩家、操作ID、預期revision、目標路線與設定版本。輸出：物品實例、經驗變化、升級結果、新錢包與revision。步驟順序固定：操作去重 → 鎖角色／錢包 → 驗證模式與容量 → 讀操作前快照 → 扣古物 → 安全亂數抽裝 → 加經驗與升級 → 寫帳本與結果 → 一次提交。

### InventoryService.sellItems

輸入：本人itemIds與操作外層。先依ID排序後鎖物品，驗證未售出、未穿戴、未被任何配置引用、未鎖定。總售價由保存的物品等級／品質與版本計算；封存物品、加金幣、寫ITEM_SOLD與結果同交易提交。任一項失敗整筆不賣。

### BenchService.upgradeOnce

驗證目前台等與預期一致、尚未滿級、金幣足夠、非BOSS。扣款與台等+1同交易；不重新抽舊裝、不發角色經驗。升級計價與生成機率使用同一內容版本。

### 裝備與配置修改

EquipService與LoadoutService共用路線驗證器，不在UI與API各抄一份不同規則。成功後只更新指定配置並發出StatsChanged事件；普通戰鬥於下一安全tick使用新屬性，BOSS則禁止更改。

### 資料庫鎖的順序

所有修改固定先鎖player，再鎖wallet，再依item_id排序鎖items，再處理loadouts／attempt。必要時使用SELECT FOR UPDATE防止同列同時修改；鎖要在短交易內釋放，不能把動畫、網路回應或整場BOSS包在資料庫交易內。[T6]

### 自動出售不是鑑定送金幣

自動鑑定成功後，若符合玩家已確認的出售規則，再發獨立出售命令。兩筆以來源operationId關聯。若中途斷線，裝備仍在背包，金幣尚未增加；重連可查回並繼續，而不是補送一份金幣。

僅在前端把按鈕變灰不等於防重複。連點、重送、雙裝置、斷線與服務重啟，都要由操作唯一鍵、列鎖、帳本與不可重複事件共同處理。

## BOSS 建立、勝負、重連與資料遷移

### StartBossAttempt

收到召喚後停止送出新的鑑定；伺服器先等目前已取得鎖的經濟命令提交，再鎖角色檢查第30關與無進行中挑戰。保存清怪狀態與自動鑑定意圖，選定打王配置，產生不可變屬性／技能快照與亂數種子，寫attempt並切為BOSS_FIGHT。若BOSS先取得鎖，後續鑑定回BOSS_LOCKED。

### ResolveBossAttempt

worker按伺服器時鐘與固定tick計算，不信任客戶端傷害。成功時在短交易中把pending改success並進位地圖；失敗改timeout／aborted並保持第30關。條件更新只允許一個worker成功，重複通知回原結果。第12圖成功改ENDGAME_FARM，不生成第361關。

### 重連與服務重啟

客戶端重新連線先請求state，若attempt尚未完成就重建畫面；若已完成就顯示結果。worker重啟可用該場快照、版本、種子與開始時間重播最多1200個50ms刻度，結算唯一結果。不能因重啟重送通關或重開滿60秒。

### 普通刷怪的提交點

每1秒或波結束，把死亡事件、古物點數、過關與checkpoint放同交易。重啟僅從已提交checkpoint恢復；畫面上尚未ack的掉落只算暫存提示，不能提前當作可消費古物。唯一(session_id,enemy_id)阻止重播再次獲利。

### 內容更新

新內容先通過結構驗證與模擬，再發布新content_version。新BOSS用新版本；進行中的挑戰保留舊版直到結束。物品實例保留生成版本；若調整既有物品，必須提供明確遷移策略與前後差異，不能靠改名或改基底讓舊裝無聲變質。

刪除技能／職業前，先列出所有被配置引用的ID；預設不自動刪除玩家選擇。必要替換以可回滾遷移處理並寫紀錄，不在每次登入時反覆修正。
