# 真實進度模擬報告（自動產生）

內容版本：0.2-proto.2。產生指令：`npm run balance:progression`（本機離線，不使用 CI）。

> 原型模擬，不是正式平衡結論，也不代表真實玩家需要的時間（規格：不能據此宣稱保證多久能三轉）。

## 玩家模型（N）

- 用正式遊戲引擎與正式命令從 Lv1、0 金幣開始玩：有古物就鑑定（目標＝目前職業），能穿且粗略戰力變高就同時換上清怪與打王配置，其餘立即出售。
- 金幣夠就升鑑定台；到轉職等級就沿路線轉職（技能用預設配置）。
- 走到 BOSS 關立刻手動召喚；輸了就刷怪，每 5 分鐘再手動召喚一次（不使用首次自動挑戰）。
- 同一張圖卡王超過 4 小時判定為「牆」並停止該路線。每條路線 1 個種子。

## 觀察

1. 牆：14 條路線都能通關，沒有卡超過上限的圖。
2. 通關時間：126～190 分鐘（中位數 157）。
3. 換圖產出差異（各圖中位數）：第 2～11 圖 +54%～+104%，其中 +40% 是規格的每圖產出 ×1.4。第 1 圖 +920% 主要是 Lv10 轉職前只有普攻，不是換圖本身。
4. 第 1 圖用時中位數 36.6 分鐘，約佔通關中位數的 23%（見習者在 Lv10 轉職前只有普攻）；規格沒有開局節奏目標，列為待決策。
5. 最後一張圖卡王 24.9～61.0 分鐘，是各路線差距最大的地方（打王輸出差異直接變成等待時間）。
